## Product mission

Build an on-demand remote video preview and lossless-export system with this behavior:

- Original media remains on the remote host close to its storage.
- The browser client loads media metadata and timeline navigation data.
- Selecting a timeline position requests a short preview window.
- The host seeks into the original using FFmpeg.
- The host generates a normalized 720p H.264/AAC fragmented MP4 preview.
- The preview is streamed incrementally to the browser over Tailscale.
- The generated bytes are simultaneously written to a deterministic disk cache.
- Stale preview requests are cancelled.
- Identical in-flight requests are coalesced.
- Project files store timestamps and editor state, not proxy media.
- Final exports operate against the original media.
- Stream copy is preferred where source constraints permit it.
- Arbitrary frame-exact boundaries must not be falsely described as fully lossless.
- The backend binds to localhost and is exposed privately through Tailscale Serve.
- Tailscale Funnel must never be enabled.

## Approved initial stack

Use this stack unless an ADR justifies a change.

### Backend

- Standard `net/http` and standard-library primitives where practical
- SQLite for the media index, projects, durable jobs, and migrations
- FFmpeg and FFprobe as supervised subprocesses
- Context-driven cancellation
- Structured JSON logging

- React
- Vite

- Vitest for unit/component tests

- Tailscale Serve as the private HTTPS reverse proxy
- Optional Docker Compose only for development or secondary packaging

### Testing

- Go unit and integration tests
- FFmpeg fixture-based media tests
- Vitest tests
- Playwright end-to-end tests
- Shell installation and smoke-test scripts

## Non-negotiable constraints

1. Do not expose original media through a generic file-serving route.
2. Never accept arbitrary client filesystem paths.
3. Resolve media using server-generated opaque media IDs.
4. Every resolved media path must remain beneath configured media roots.
5. Bind the backend to `127.0.0.1` by default.
6. Trust Tailscale identity headers only through the configured trusted-proxy path.
7. Never enable Tailscale Funnel.
8. Do not construct FFmpeg commands through shell interpolation; pass argument arrays.
9. Every FFmpeg process must:
   - inherit a cancellable context;
   - capture bounded stderr;
   - terminate on client disconnect or supersession;
   - write incomplete cache output to a temporary file;
   - atomically rename only after successful completion.
10. Bound preview concurrency globally and per user.
11. Isolate export concurrency from preview concurrency.
12. Deduplicate identical in-flight previews with single-flight semantics.
13. Include media fingerprint and preview-profile version in cache keys.
14. Never call a non-keyframe stream-copy result frame-exact.
15. Do not claim hardware acceleration works until a real capability test transcode passes.
16. Retain a software encoder fallback.
17. Do not merge code that fails acceptance tests.
18. Avoid infrastructure that is not required by the MVP.
19. Prefer explicit maintainable code over clever abstractions.
20. Keep commits small enough to review.

## Preview normalization

Use configurable defaults similar to:

```text
before: 2 seconds
after: 6 seconds
maximum total duration: 15 seconds
cache grid: 500 milliseconds
maximum preview size: 1280x720
frame rate: 30 fps
audio: AAC stereo 48 kHz
video: H.264
container: fragmented MP4
```

Normalize:

- center into media duration;
- start near file boundaries so the requested window remains valid;
- timestamps to integer milliseconds for keys;
- near-identical centers onto the cache grid.

The selected original timestamp must map exactly to the returned preview offset value.

## Cache requirements

The cache must:

- hash canonical key data with SHA-256;
- shard storage by hash prefix;
- include media ID, source size, and nanosecond mtime;
- include normalized start and duration;
- include dimensions, frame rate, audio state, and encoder-profile version;
- use an incomplete suffix for partial output;
- atomically rename after success;
- never serve partial files;
- update access metadata on hit;
- support bounded eviction;
- invalidate naturally when the source fingerprint changes.

## Scheduling priorities

Use this order:

1. current foreground preview;
2. cancellation/control actions;
3. adjacent preview prefetch;
4. thumbnail generation;
5. background indexing;
6. cache maintenance.

A newer foreground request from the same user supersedes the older request. Export jobs must not consume every preview slot.

## Hardware acceleration

At startup or on demand:

1. inspect FFmpeg encoders and devices;
2. run a short real test transcode for each candidate profile;
3. record successful profiles;
4. choose the preferred successful profile;
5. fall back to software on failure;
6. expose the chosen profile in diagnostics;
7. avoid retrying known-broken hardware for every request.

The host may configure a preference such as:

```text
NVENC → VAAPI/QSV → libx264
```

Do not assume this order is universally optimal.
