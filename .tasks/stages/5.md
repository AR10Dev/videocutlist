## Frozen contract

- This stage preserves behavior; it does not redesign media, cache, project,
  export, or job protocols.
- Preview responses remain fragmented MP4 and publish bytes before the producer
  completes.
- Cancelling a client detaches that subscriber; the producer stops only when no
  subscribers remain. A newer request from the same principal does not cancel a
  shared producer still used by another subscriber.
- Identical normalized previews coalesce to one producer. Global and
  per-principal limits remain bounded.
- Cache misses stream through a temporary partial and publish only after
  producer success plus validation and atomic rename. Hits do not spawn a new
  producer; invalid/abandoned partials never become hits.
- Projects retain opaque-subject ownership and optimistic revisions.
- Final exports resolve and read original media server-side; client responses
  never contain original paths, cache paths, export paths, or provider metadata.
- Existing API status, preview diagnostic headers, cancellation, and safe error
  contracts remain unchanged.

## Acceptance criteria

1. An integration test proves first preview bytes arrive before producer exit.
2. Cancellation, last-subscriber termination, shared-subscriber survival, and
   duplicate coalescing are deterministic under the race detector.
3. Cache miss, validated atomic publication, hit-without-spawn, invalid partial,
   and abandoned partial behavior are covered.
4. Global/per-principal preview bounds remain covered.
5. Project save/load and optimistic revision behavior pass.
6. Export input uses the resolved original and incomplete/cancelled outputs are
   never published.
7. API responses and errors contain no filesystem path or provider metadata.
8. Ordinary HTTP integration, full Go race, web, and smoke gates pass.
9. No dependency, public contract, deployment, or unrelated change.
