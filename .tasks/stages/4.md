## Frozen contract

### Principal and authenticator

- Replace Tailscale-specific identity/capability types with the exact generic
  `Principal` and `Authenticator` interface in the runtime contract.
- `auth.New(Config)` returns an `Authenticator`; API configuration accepts the
  interface, never a concrete adapter.
- Subject is the only ownership/rate-limit key propagated into lower-level
  services. API/application service boundaries receive `auth.Principal`.
- `Principal.Allows(action, resource)` accepts `*`, `action`, or
  `action:resource`.

### Modes

- Configuration modes: `none` (default), `bearer`, `trusted_proxy`.
- None: ignore credentials; anonymous principal with editor role and `*`.
- Bearer: require a non-empty control-free configured token; accept exactly one
  Bearer Authorization value; compare the token in constant time; subject
  defaults to `static-bearer`.
- Trusted proxy: read only `httpx.GetForwardedInfo(request.Context()).User`;
  never consume raw forwarded/provider identity headers.
- Subjects use the frozen opaque validation. Built-in successful modes receive
  editor role and `*`.
- The interface is sufficient for a future OIDC adapter; add no dependency or
  incomplete OIDC implementation.

### Authorization and safety

- API authorization consumes generic principals and capabilities.
- Authentication failure is 401; authorization failure is 403.
- Authentication and authorization occur before any media refresh, preview
  start, project operation, job operation, or export creation.
- Structured API logs use `principal_subject`, never `user_login`.
- Remove active Tailscale header parsing, capability JSON, modes, and types from
  core code and the OpenAPI runtime contract.

## Acceptance criteria

1. None, correct bearer, wrong/missing/multiple bearer, trusted proxy, and
   untrusted spoof flows are covered.
2. Constant-time static token comparison and strict header parsing are visible
   in source.
3. Generic principals cross API/application boundaries; lower layers use only
   opaque Subject where a string key is required.
4. Capability allow/deny behavior is covered.
5. Failed authentication/authorization cannot invoke preview/FFmpeg, refresh,
   project, job, or export adapters.
6. No Tailscale header/type/mode remains in `cmd` or `internal`.
7. No OIDC dependency, server networking change, or unrelated behavior.
