## Frozen contract

### CORS

- Add `httpx.CORS(allowedOrigins []string, next http.Handler) http.Handler`.
- No `Origin` means an ordinary request and passes unchanged.
- A supplied origin must exactly match the configured allowlist; wildcard and
  suffix matching are forbidden.
- Allowed actual responses echo the origin, allow credentials, vary on Origin,
  and expose the runtime-contract response headers.
- Valid preflight methods: GET, HEAD, POST, PUT, DELETE.
- Valid requested headers: Authorization, Content-Type, If-Match,
  If-None-Match, compared case-insensitively.
- Valid preflight returns 204 before authentication. Disallowed/malformed
  cross-origin requests return 403 before application services execute.

### Trusted proxy

- Add `httpx.TrustedProxy(trustedCIDRs []string, next http.Handler)
  (http.Handler, error)`, `httpx.ForwardedInfo`, and
  `httpx.GetForwardedInfo(context.Context)`.
- Recognized headers are `X-Forwarded-For`, `X-Forwarded-Host`,
  `X-Forwarded-Proto`, and `X-Forwarded-User`.
- Always strip recognized headers before the downstream handler.
- Ignore values from an untrusted immediate peer and expose transport-derived
  defaults with no identity.
- For a trusted peer, validate all forwarded values. Determine client IP by
  walking X-Forwarded-For right-to-left across trusted hops and stopping at the
  first untrusted IP.
- Preserve the immediate peer separately. Do not rewrite `RemoteAddr`.
- Malformed trusted forwarded values return 400 before downstream execution.

### Wiring

- Order: CORS outermost, trusted proxy, then the existing mux.
- Use only `AllowedOrigins` and `TrustedProxyCIDRs`; add no provider-specific
  configuration or dependency.

## Acceptance criteria

1. Empty allowlist denies every request carrying Origin.
2. Exact allowed actual requests and preflights receive only the frozen headers.
3. Wildcard, suffix, disallowed method/header, and malformed preflights fail.
4. Untrusted spoofed forwarded identity/address/host/protocol never reaches
   downstream context or raw headers.
5. Trusted chains, IPv4/IPv6 peers, host/protocol, and optional identity parse
   deterministically; malformed trusted data fails closed.
6. Preflights do not authenticate or invoke application/media services.
7. Middleware order is CORS → trusted proxy → existing mux.
8. No Tailscale-specific rule, server dependency, or unrelated change.
