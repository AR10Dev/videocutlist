# Stage 6 — Deployment and Documentation Separation

**State:** CONTRACT_FROZEN

## Lifecycle

`PLANNED -> CONTRACT_FROZEN`

## Frozen contract

- The primary install and operations path has no Tailscale executable,
  service, environment-variable, or policy dependency.
- The primary flow is: start the server, obtain a reachable HTTP(S) URL,
  configure the browser client with that URL, then configure application
  authentication when required.
- The default systemd example binds loopback. A documented LAN deployment may
  explicitly bind a non-loopback IP literal and must explain host firewall and
  authentication requirements.
- The neutral verifier checks only EditApp health, readiness, process state,
  and the configured listener. Provider checks remain in optional provider
  guidance.
- Tailscale Serve remains an optional private-connectivity example. Funnel is
  never enabled or recommended.
- Connectivity examples may describe LAN, Tailscale, WireGuard, SSH tunnels,
  and public HTTPS. They do not change the binary or core application
  contracts.
- No Docker image or proxy configuration is added unless it is executable and
  verified in this stage; documentation may use the existing systemd install
  and generic reverse-proxy contract instead.

## Ownership

- `terra-stage-6-impl-1`: primary neutral install, service, operations, and
  top-level documentation.
- `terra-stage-6-impl-2`: optional connectivity and reverse-proxy examples.
- `terra-stage-6-test-1`: deployment static checks and clean-environment smoke.
- The controller alone owns contracts, this task ledger, and integration.

## Acceptance criteria

1. A new primary README works for localhost and LAN without Tailscale.
2. The systemd environment uses current listener and auth variables.
3. The installer neither installs nor invokes Tailscale and its completion
   instructions start only EditApp.
4. Neutral deployment verification succeeds without `tailscale`, `tailscaled`,
   or provider environment variables present.
5. Client base-URL and none/bearer/trusted-proxy authentication setup are
   accurate and match the frozen runtime contract.
6. Optional connectivity guides are clearly secondary and never enable Funnel.
7. Shell/static deployment checks and a clean-environment installation smoke
   test pass.
8. `make check`, `make test`, and `make smoke` pass.
9. No production Go/web code, public API contract, dependency, or unrelated
   file changes.
