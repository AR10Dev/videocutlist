# Advanced editing plan

This work ships in serial milestones. Each milestone has one writer, tests, review, and validation before the next begins. Original-media paths remain server-only. FFmpeg and FFprobe keep argument arrays, inherited file descriptors, cancellable contexts, bounded stderr, and atomic publication.

## Shared test seams

- Client timeline module: Vitest for history, viewport mapping, asset normalization, and candidate acceptance.
- HTTP contract: Go integration tests for bounded input, authentication, authorization, localhost-only automation, and path-safe responses.
- Media processing: real FFmpeg/FFprobe tests generated by `test/harness/generate-fixtures.sh`.
- Browser: Playwright tests with deterministic timeline asset responses. Browser tests verify user flows and stale-request cancellation, not media decode quality.

## Milestone 1: timeline state and undo/redo

Extract a pure timeline module from `client/src/App.tsx`. It owns immutable snapshots of playhead, in/out markers, ordered segments, and viewport zoom. The module exposes edit, undo, redo, and reset operations. The app uses it at the shared editor mutation point and adds Undo/Redo buttons plus Cmd/Ctrl-Z, Cmd/Ctrl-Shift-Z, and Ctrl-Y.

Acceptance: a changed timeline is restored exactly by undo, a new edit clears redo, project load/new media resets history, and existing marker/segment behavior still works.

## Milestone 2: visual timeline, thumbnails, and waveform

Replace the timeline range-only presentation with an accessible DOM timeline while retaining the native range fallback. Add bounded, cached server endpoints for contact-sheet thumbnails and waveform peaks, keyed only by opaque media ID and normalized request parameters. Each endpoint uses an already-open descriptor and never returns original paths. The client fetches both assets independently, aborts stale requests, renders segment/marker/playhead overlays, and reports unavailable assets without disabling editing.

Acceptance: supported media produces bounded thumbnail and waveform requests; media change cancels stale work; no-audio media renders a clear fallback; asset errors preserve editing; timeline zoom changes only viewport rendering.

## Milestone 3: opt-in auto detection

Add explicit, cancellable detection jobs for silence, black frames, and scene changes. Results are candidates with source and confidence. They never modify segments until the user accepts a candidate. Candidates are rejected if their media/project version is stale.

Acceptance: queued/running/succeeded/failed/cancelled jobs are safe to poll and cancel; accepted candidates pass normal overlap validation; rejected candidates do not alter a project.

## Milestone 4: interchange

Add bounded CSV and chapter text adapters over `domain.Document`. CSV carries ordered ranges and labels. Chapter text carries start times and titles, deriving end times from the next chapter or media duration. Reject paths, unknown fields, oversized input, invalid timestamps, duplicates, and zero-length ranges. Expose import/export through authenticated project routes and browser controls.

Acceptance: known cut lists round-trip through canonical segments, malformed files fail closed, and no input/output contains a filesystem path.

## Milestone 5: hybrid Smart Cut

Add a new, explicitly experimental strategy after keyframe probing is available. Start with H.264 CFR MKV only. Re-encode each requested boundary through the next compatible keyframe, then stream-copy the remaining span. Keep full `precise_reencode` as an explicit fallback. Do not call any result frame-exact unless output probe evidence supports it.

Acceptance: H.264 long-GOP fixture has accurate starts, valid output, atomic cancellation cleanup, and truthful warnings. VFR/H.265 remain rejected or fall back until their own fixture matrix passes.

## Milestone 6: local automation API

Add a small command allowlist for project import/export and job status. It requires existing authentication and is rejected unless the listener is loopback. Browser-origin requests remain rejected. Requests have strict body limits and return opaque IDs and safe filenames only.

Acceptance: real HTTP tests reject non-loopback and unauthenticated requests, allow authenticated loopback callers, enforce action and body limits, and never reveal source or export paths.

Contract: `POST /api/v1/automation` accepts only `project.import`, `project.export`, and `job.status`. It requires configured authentication, a loopback listener, no `Origin` header, and a body no larger than 1 MiB. Import and export use opaque `projectId` values and `csv` or `chapters`; responses contain only opaque IDs, interchange content, or safe filenames.

## Fixture matrix

Use `test/harness/generate-fixtures.sh` for H.264 long-GOP, VFR, multi-audio, no-audio, corrupt, and capability-gated HEVC fixtures. Each media-processing test verifies FFprobe output and published files, not only FFmpeg exit status.
