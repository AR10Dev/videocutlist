# Real-media validation and performance evidence

`.github/workflows/real-media.yml` runs weekly (Monday at 03:17 UTC) and on manual dispatch. The job has a 30-minute total timeout; ordinary pull requests do not download media or run these performance workloads. GitHub retains the run artifact for 14 days, including the checksum-verified fixture when acquisition succeeds and backend benchmark CSV output. Upload runs even after test failure so partial evidence remains available; the workflow still fails when either harness fails.

`make test-real-media` obtains `test/fixtures/real-media/sintel-trailer.mp4` through `test/harness/acquire-real-media.sh`, which verifies SHA-256 against the pinned fixture digest, then runs the tagged Go real-media tests and Playwright real-media suite. The benchmark harness `make benchmark-backend` runs API and media workloads against disposable local servers and emits CSV; its media phase reuses the same acquisition script. Performance results are evidence, not pass/fail latency thresholds: shared-runner load, filesystem, CPU scheduling, and short-lived process sampling make absolute timings noisy. Compare like-for-like runs and treat resource sidecar sampling as observational.
